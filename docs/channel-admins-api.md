# Админы каналов — API для бэкенда

Клиент: `app/src/main/java/com/example/vibic/channel/`. Сейчас работает на заглушке
`FakeChannelAdminRepository`, правила — в `ChannelAdminPolicy`. Сервер должен проверять те же правила сам:
клиенту доверять нельзя.

## Роли и права

Роли: `owner` (ровно один на канал), `admin`, `subscriber`.

Объект прав (все поля boolean):

```json
{
  "change_profile": false,
  "post_messages": true,
  "edit_others_posts": false,
  "delete_others_posts": false,
  "invite_users": true,
  "ban_users": false,
  "manage_live": false,
  "view_stats": true,
  "add_admins": false
}
```

Если `rights` не передан при назначении, ставим такие права (как в примере): `post_messages`, `invite_users`, `view_stats`.

## Правила, которые проверяет сервер

1. У владельца всегда все права. Менять, снимать или назначать владельца через эти эндпоинты нельзя.
2. Назначать и редактировать админов может владелец или админ с `add_admins = true`.
3. Админ может выдать только те права, которые есть у него самого. У владельца ограничений нет.
   При редактировании права, которые у админа уже есть, можно оставить, даже если у редактирующего их нет.
4. Редактировать права и снимать админа может владелец или тот, кто его назначил (`promoted_by`).
   Для редактирования у назначившего должно быть право `add_admins`, для снятия оно не нужно.
5. `custom_title` — не длиннее 16 символов.
6. Передать владение может только владелец и только действующему админу канала, с паролем.
   Бывший владелец становится админом со всеми правами, новый владелец удаляется из списка админов.
   Всё это нужно сделать в одной транзакции.
7. Если админа снимают, назначенные им админы остаются. Ими дальше управляет владелец.

## Эндпоинты

### `GET api/chats/{chatId}/admins`

Видят все участники канала (так подписчик понимает, кто подписывает посты).

```json
{
  "channel_id": "c1",
  "owner_id": "u1",
  "admins": [
    {
      "user_id": "u2",
      "name": "Alice",
      "avatar_url": "https://…",
      "custom_title": "редактор",
      "rights": { "…": "…" },
      "promoted_by": "u1",
      "promoted_at": "2026-11-05T12:00:00Z"
    }
  ]
}
```

### `POST api/chats/{chatId}/admins` — назначить админа

```json
{ "user_id": "u3", "rights": { "…": "…" }, "custom_title": "" }
```

`rights` и `custom_title` необязательны. `promoted_by` и `promoted_at` сервер ставит сам.
Ответ: `201` и объект админа, как в списке выше.

### `PATCH api/chats/{chatId}/admins/{userId}` — изменить права или подпись

```json
{ "rights": { "…": "…" }, "custom_title": "модератор" }
```

Оба поля необязательны. `rights` передаётся целиком, а не частично. Ответ: `200` и объект админа.

### `DELETE api/chats/{chatId}/admins/{userId}` — снять админа

Ответ: `204`. Пользователь остаётся подписчиком канала.

### `POST api/chats/{chatId}/transfer-ownership` — передать канал

```json
{ "new_owner_id": "u2", "password": "…" }
```

`password` — пароль двухэтапной проверки (уже есть `api/auth/setup-2fa`). Если 2FA не включена,
вернуть `two_fa_required`: без пароля передавать канал нельзя. Число попыток нужно ограничить.
Ответ: `200` и тот же объект, что в `GET …/admins`, уже с новым владельцем.

## Ошибки

Тело: `{ "error": "<code>", "message": "…" }`

| HTTP | `error`              | Когда                                              |
|------|----------------------|----------------------------------------------------|
| 404  | `channel_not_found`  | нет канала или это не канал                        |
| 403  | `not_allowed`        | у того, кто делает запрос, нет прав на это действие |
| 403  | `owner_rights_locked`| попытка изменить, снять или назначить владельца     |
| 403  | `rights_exceed_own`  | выдаются права, которых нет у назначающего         |
| 409  | `already_admin`      | пользователь уже админ                             |
| 404  | `not_admin`          | пользователь не админ (при правке, снятии, передаче) |
| 400  | `title_too_long`     | `custom_title` длиннее 16 символов                 |
| 403  | `wrong_password`     | неверный пароль при передаче канала                 |
| 400  | `two_fa_required`    | у владельца не включена 2FA                        |
| 429  | `too_many_attempts`  | слишком много попыток ввода пароля                 |

Клиент сопоставляет `error` с `ChannelAdminError`.

## WebSocket-события

Чтобы список админов и права обновлялись без перезахода в канал:

- `channel_admin_promoted` — `{ chat_id, admin }`
- `channel_admin_updated` — `{ chat_id, admin }`
- `channel_admin_demoted` — `{ chat_id, user_id }`
- `channel_owner_changed` — `{ chat_id, owner_id, previous_owner_id }`

## Что поменять в текущем API

- `POST api/chats/{chatId}/participants/{userId}/role` сейчас умеет ставить `admin` без прав и без
  проверки, кто назначает. Для каналов этот путь нужно закрыть или перенаправить на правила выше.
- `GET api/chats/{chatId}/participants` для каналов должен отдавать роль `subscriber` вместо `member`.
- В `ChatDto` полезно добавить `my_role` и `my_rights`, чтобы клиент мог показать или скрыть кнопки,
  не запрашивая отдельно список админов.

## Для экрана профиля канала

Экран владельца и админа (`ChannelProfileActivity`) ждёт ещё вот что:

### `GET api/chats/{chatId}/stats` — статистика (нужно право `view_stats`)

```json
{
  "subscribers_growth": 12,
  "post_reach": 840,
  "post_reach_growth_percent": 8.0,
  "er_percent": 4.2,
  "er_growth_points": 0.3
}
```

Всё за последние 7 дней, прирост — к предыдущим 7 дням. Сейчас клиент показывает **демо-цифры**
из `FakeChannelStatsRepository`. Перед релизом их нужно заменить на этот эндпоинт.

### Поля в `GET api/chats/{chatId}` для каналов

- `username` — @username публичного канала, `null` у частного. Клиент уже читает это поле.
- `participants_count` — уже есть, используется как число подписчиков.
